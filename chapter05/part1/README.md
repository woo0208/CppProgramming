# 실습과제 01

## 1. 인자와 매개변수를 구분하여 설명하시오.
*   **매개변수 (Parameter / 형식 매개변수):** 함수가 호출될 때 전달받을 값을 저장하기 위해 함수 선언부 및 정의부에 선언된 변수입니다. (예: `void func(int a)`에서 `a`)
*   **인자 (Argument / 실인자):** 함수를 호출할 때 함수로 실제로 전달하는 값 또는 변수입니다. (예: `func(10)`에서 `10`)

## 2. 함수 호출 시 자동으로 처리되는 2가지는 무엇인가?
1.  **반환 주소(Return Address) 저장:** 함수 실행이 완료된 후 호출자(Caller)의 다음 명령어로 돌아가기 위해 현재의 실행 위치(프로그램 카운터 값)를 스택(Stack)에 푸시(Push)합니다.
2.  **스택 프레임(Stack Frame) 할당 및 매개변수 초기화:** 호출되는 함수를 위한 독립적인 메모리 공간인 스택 프레임이 생성되며, 전달된 인자 값이 복사되어 매개변수가 초기화됩니다.

## 3. 값에 의한 호출(Call-by-value)로 다른 함수에서 선언된 변수의 값을 변경할 수 없는 이유를 설명하라.
값에 의한 호출은 인자의 원본 메모리 주소가 아닌, 변수에 저장된 **'값의 복사본'**을 함수의 매개변수로 전달합니다. 호출된 함수 내부에서 생성된 매개변수는 별도의 스택 프레임에 존재하는 독립적인 지역 변수이므로, 함수 내부에서 이 값을 수정하더라도 복사본만 변경될 뿐 호출자의 원본 변수 메모리에는 어떠한 영향도 미치지 않습니다.

## 4. 주소에 의한 호출(Call-by-address/reference)을 사용해야 하는 경우를 2가지 이상 설명하라.
1.  **호출자의 원본 데이터를 수정해야 할 때:** 함수 내부의 연산 결과를 반환값 하나로만 처리하기 어렵고, 두 개 이상의 변수를 직접 변경해야 하는 경우(예: `swap` 함수) 원본 메모리 주소를 전달하여 직접 접근해야 합니다.
2.  **메모리 및 성능 오버헤드를 방지해야 할 때:** 크기가 큰 구조체나 배열 등을 인자로 전달할 때, 값에 의한 호출을 사용하면 전체 데이터의 복사가 발생하여 메모리 낭비와 성능 저하가 일어납니다. 주소만 전달하면 4바이트 또는 8바이트의 포인터 크기만큼만 복사되므로 효율적입니다.

## 5. 인자가 객체인 경우는 어떤 호출 방식이 좋은가? 이유도 설명하라.
인자가 객체인 경우 **'상수 참조에 의한 호출 (Call-by-const-reference, 예: `const ClassName& obj`)'** 방식을 사용하는 것이 가장 좋습니다.
*   **이유:** 객체를 값에 의한 호출로 전달하면 묵시적으로 복사 생성자(Copy Constructor)가 호출되어 객체 내부의 모든 멤버 변수가 복사되는 심각한 오버헤드가 발생합니다. 참조(&)를 사용하면 주소만 전달되어 복사 비용이 발생하지 않으며, `const`를 붙여 전달함으로써 함수 내부에서 원본 객체의 상태를 의도치 않게 변경하는 것을 컴파일러 단에서 방지할 수 있어 성능과 안전성을 모두 확보할 수 있습니다.

## 6. 함수 반환 과정에서 자동으로 처리되는 2가지는 무엇인가?
1.  **반환 값(Return Value)의 임시 객체 생성 및 복사:** 함수가 반환할 값을 호출자에게 안전하게 전달하기 위해 레지스터(Register)나 별도의 임시 메모리 공간에 반환 값을 복사합니다.
2.  **스택 프레임 소멸 및 실행 흐름 복귀:** 호출되었던 함수의 지역 변수와 매개변수들이 메모리(스택)에서 해제(객체의 경우 소멸자 호출 포함)되고, 함수 호출 시 스택에 저장해 두었던 반환 주소를 팝(Pop)하여 호출자의 원래 실행 흐름으로 되돌아갑니다.

## 7. 함수 반환 과정에서 임시 변수가 필요한 이유를 설명하라.
함수가 종료되는 시점에 해당 함수의 스택 프레임은 파괴되며, 그 안에 존재하던 모든 지역 변수는 메모리에서 해제됩니다. 만약 반환 값을 지역 변수 메모리에 그대로 둔다면, 제어권이 호출자에게 넘어간 직후 해당 메모리는 쓰레기 값(Garbage value)으로 덮어씌워질 위험이 있습니다. 따라서 함수가 완전히 소멸되기 직전에, 호출자의 스택 프레임이 파괴된 후에도 호출자가 안전하게 접근하여 읽을 수 있는 중립적인 메모리 공간(레지스터 또는 호출자 측의 임시 변수 공간)에 반환 값을 미리 복사해 두어야 데이터를 안전하게 전달할 수 있기 때문입니다.
