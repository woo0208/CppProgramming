# 실습과제 1

## 1. static 멤버 변수를 클래스 선언부에 선언하고 외부에서 다시 정의(초기화)하는 이유

C++에서 static 멤버 변수를 클래스 내부에서 선언만 하고 외부 소스 파일(.cpp)에서 다시 정의하는 가장 핵심적인 이유는 단일 정의 원칙(ODR, One Definition Rule)을 준수하고 메모리를 단 한 번만 할당하기 위해서입니다.

* **선언(Declaration)과 정의(Definition)의 분리:** 클래스 선언부(주로 헤더 파일)에 작성하는 `static int count;`와 같은 코드는 컴파일러에게 "이러한 타입과 이름의 정적 변수가 존재한다"고 알려주는 단순 **선언**입니다. 이 단계에서는 실제 메모리(데이터 영역)가 할당되지 않습니다.
* **중복 정의 에러(Multiple Definition Error) 방지:** static 변수는 객체의 인스턴스와 무관하게 프로그램 전체에서 단 하나의 메모리 공간을 공유해야 합니다. 만약 헤더 파일의 클래스 내부에서 메모리 할당(정의 및 초기화)까지 수행한다면, 해당 헤더를 `#include` 하는 여러 번역 단위(Translation Unit, 개별 .cpp 파일)마다 동일한 변수가 중복으로 생성됩니다. 이로 인해 링커(Linker) 단계에서 중복 정의 에러가 발생하게 됩니다.
* **정확한 메모리 할당:** 따라서, 선언은 헤더 파일의 클래스 내부에 두어 접근 권한과 소속을 명시하고, 실질적인 메모리 할당을 동반하는 **정의**는 단 하나의 소스 파일(.cpp) 전역 스코프에서 단 한 번만 수행하도록 문법적으로 강제하는 것입니다.

## 2. static 멤버 함수의 외부 구현부에 static 키워드를 붙이면 안 되는 이유

클래스 외부에서 static 멤버 함수를 구현할 때 `static` 키워드를 생략해야 하는 이유는 C++에서 위치에 따라 달라지는 **static 키워드의 의미 충돌(링크 속성 문제)** 때문입니다.

* **위치에 따른 static의 의미 차이:**
  * **클래스 내부:** 객체가 아닌 클래스 자체에 종속되는 멤버임을 의미합니다.
  * **클래스 외부(전역 스코프):** 해당 식별자가 **내부 링크(Internal Linkage)** 속성을 갖도록 만듭니다. 즉, 해당 변수나 함수가 선언된 현재의 소스 파일(번역 단위) 내부에서만 접근할 수 있도록 가시성을 제한합니다.
* **논리적 모순과 컴파일 에러:** 클래스의 멤버 함수는 기본적으로 다른 파일에서도 호출할 수 있어야 하므로 **외부 링크(External Linkage)**를 갖습니다. 컴파일러는 헤더 파일의 클래스 선언부를 통해 해당 함수가 클래스 소속의 정적 멤버임을 이미 인지하고 있습니다. 
* 그런데 외부 구현부에 또다시 `static`을 붙이게 되면, 컴파일러는 이를 "이 함수를 현재 .cpp 파일에서만 사용할 수 있는 전역 함수로 만들겠다"는 내부 링크 지정으로 해석하게 됩니다. 이는 클래스 멤버로서의 속성과 정면으로 충돌하는 문법적 모순이므로, C++ 표준에서는 이를 허용하지 않고 **컴파일 에러**를 발생시킵니다.
